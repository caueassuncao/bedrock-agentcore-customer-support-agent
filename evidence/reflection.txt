Reflection

Design decision. I keyed long-term memory to the customer (customer_id as the memory actor) rather than to the session. The MemoryHook retrieves facts and preferences for that customer on every plain-text user message, prepends them as "Customer Context", and saves each completed turn after the agent responds. I chose this because long-term memory only matters if it survives across sessions: Jane introduced herself in one session, and a brand-new session correctly recalled her name and preference for concise answers. Scoping by session would have made that impossible.

Challenge. My biggest challenge was that refunds failed silently after deployment: the model covered the failure with plausible but invented answers. The runtime logs showed the agent calling refund-processor___DefaultTool, meaning the Gateway target still held a placeholder schema instead of initiate_refund, check_refund_status and get_return_label. Updating the target with the real schema fixed the refund. A follow-on problem was that the invented refund amount had been extracted into long-term memory and kept resurfacing as fact, so I deleted those records and added system-prompt rules to ground answers in tool results. Missing IAM permissions and CodeBuild being blocked in my lab account (solved by building the image locally) were smaller obstacles solved the same way: read the logs first, then apply a targeted fix.

Production extension. For production, I would authenticate the Gateway (it currently has no authorizer) with JWT or IAM, and take the customer's identity from the verified token instead of trusting customer_id in the payload. Refunds need guardrails: ownership checks, amount limits, idempotency keys and human approval above a threshold. Memory should store only verified facts, never unverified assistant claims or tool errors. I would also apply least-privilege IAM, allowlist browser domains, add alarms and evaluation tests on the CloudWatch/X-Ray traces, and define the Gateway schema and role policies as infrastructure as code so they are reproducible instead of console-edited.
